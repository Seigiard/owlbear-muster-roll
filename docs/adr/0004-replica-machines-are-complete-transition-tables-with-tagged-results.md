# Replica machines are complete transition tables; failures are tagged results; Effect waits

At acceptance on 2026-11-18, after three grilling rounds with the owner and a second reviewer's read, `src/replica` holds the room's state machines in four shapes: a decision-list module (`catch-up`), injected-port modules (`generation-flow`, `room-protocol`, `roll-flow`, `room-copy`, `pending-edits`), a pure router (`command-routing`) and 1500 lines of wiring in `engine.ts`. Nothing checks that every phase answers every event: `switch` statements guarded by `never` helpers cover message kinds, not phase-event pairs, and eight pairs in `catch-up` answer with a silent empty list. Failures leave the replica through 86 `console.error` calls in seven patterns; the port failures `SendFailure` and `StorageFailure` are object literals with no exhaustive handling, and a domain verdict such as `too-large` reaches the player as "no write access". Stopping is a `stopped` flag in six modules, five epoch counters and a `stop()` of thirteen calls. The owner asked for a simpler core, typed errors, and state machines whose completeness is checked automatically.

The decision has four parts, in the order they land:

1. **Every replica state machine is a transition table.** A module exports `Phase`, `Event` and `Effect` unions and a `TransitionTable<Phase, Event, Effect>` whose type requires one cell per phase-event pair; a cell is a function or the literal `'ignore'`. A missing cell is a compile error (TS2741 in the spike). Phases and events use `kind`, and effects use `type`. A conditional no-op inside a cell is that cell's decision and is covered by its table test, not by the shared check. The shared check samples each non-`ignore` cell with generated data, checks invariants and keeps a Mermaid diagram of the sampled transitions in sync with the code. The modules keep running their own effects; the table replaces the `switch` and the closure variables, not the module boundary. The GM link is a second table in `catch-up-table.ts`, fed by the same shell. It starts `offline`. The roll flow's `gmInParty` predicate checks the party list, not liveness.
2. **Lifecycle and time become ports, in plain TypeScript.** The engine owns one `AbortController` and shares its `signal` with helpers that need cancellation. `schedule(signal, ms, fn)` cancels its timer on abort, and engine subscriptions unsubscribe on abort. `stop()` is one `abort()`. The outbox discards held commits and acknowledgements. A room-copy write that already went out can still finish read-back, publish its status and resolve a waiting import. The epoch counters that detect an answer superseded by a newer request stay, and are the first item of the Effect revisit. `Platform.clock` supplies wall time and scheduling through `{ now, schedule }`, with OBR and mock adapters. The replica no longer reads `Date.now` or `performance.now` directly. TASK-116 moved three engine test files to the rig's manual clock. The rest keep real time.
3. **`better-result` replaces `src/core/result.ts` across the project.** `src/platform/ports.ts` defines the `TaggedError` classes. The room-copy shell reports a rejection from `metadata.setMetadata` as `MetadataFailure`; that port still returns `Promise<void>`. Each module decides whether to retry, keep the old value or wait. The failure sink accepts `report(failure: ReplicaFailure)` and uses exhaustive `.match` to format its diagnostic detail. Windows receive its bounded list as a `diagnostics` field, and only GMs see the collapsed block in Settings. Tests can inspect reports and diagnostics instead of spying on the console. Domain verdicts keep their reason. Bugs stay thrown, which the library reports as `Panic`.
4. **Effect is deferred.** It would add a fiber runtime, `Scope`, `Queue` and `TestClock` at 17 KB gzip and a rewrite of the engine. Parts 2 and 3 take the two things it would have replaced first, so the decision is reopened on evidence: the engine tests stay racy after the clock port; places remain where one `AbortSignal` is not enough; or the `roomMessages` chain, the room-copy write mutex or the six hand-written backoffs need a second copy.

## Consequences

- `machine.ts` (the table type and `step`) and `tests/support/machine-check.ts` are plain TypeScript with `fast-check`, already a dev dependency. No runtime library enters for part 1.
- `catch-up` is the first table because it already returned decisions as data. Its interpreter and timer registry move to `catch-up-effects.ts`, and the engine loses 128 lines. The engine keeps the four send ports. `room-copy-table.ts` and `generation-table.ts` follow. `room-protocol`, `pending-edits` and `roll-flow` stay linear. `saveAdoption` stays synchronous, and `catch-up.ts` still checks the request nonce.
- `better-result` is the one `Result` in the repository. The swap replaced `.ok` checks and plain result objects with `Result` instances without changing their payloads. Cost: 3.4 KB gzip, zero dependencies, TypeScript 7.0.2 compiles it. The port error classes stay beside their ports, so ADR-0003's rule for core holds.
- Core keeps zod for the wire and the preset. UI flows keep the ADR-0002 reducer shape; a UI reducer may use the same table type when a flow has more than one phase, but nothing requires it.
- The TASK-63 and TASK-64 criterion "no shared state-machine runtime is introduced" stands: a table type, a signal and a test helper are not a runtime. What changes is the shape rule: one shape for the state of every replica machine, so one check covers them all.
- Timers remain schedulers, as CLAUDE.md requires: a timer fires an event into the table; the cell decides.
- The `better-result` swap lands after TASK-114.3, the last of the three block-address PRs, and the failure sink after it; TASK-114.2 touches the same engine lines and adds one more parse drop that should go through `report` from the start. The catch-up tables, the `AbortSignal` and the clock port do not depend on either and run in parallel with TASK-114.
- `GLOSSARY.md` gains the two GM terms: the online GM, by messages, and the GM in the party, by the list.
- The module boundaries stay for this decision, not for ever. The 2026-11-18 architecture review (candidate 2) proposed merging `command-routing`, `room-protocol`, `generation-flow` and `roll-flow` into the engine because each takes 15 to 23 callback ports from it with one adapter. The owner deferred that on 2026-11-19 until this decision's last step has landed, because parts 2 and 3 remove `stopped`, timers and failure reporting from every fan. After step 8 the fans are measured again (TASK-122): a module still wider than about 10 ports with one adapter is a merge candidate, and this ADR is amended with the answer.
  - **Amendment, 2026-11-20 (TASK-122).** Measured at 84b1218, after step 8: `RoomProtocolPorts` 25 fields, `CommandRoutingPorts` 24, `GenerationFlowPorts` 23, `RollFlowPorts` 17. Each module has one adapter, `startReplicaEngine` in `engine.ts`. Parts 2 and 3 did not narrow the fans, so all four are still merge candidates. The owner decided on 2026-11-20 to keep all four as separate modules with their ports. The reason is the edit-delivery work: TASK-125, TASK-132, TASK-103, TASK-102, TASK-106 and TASK-99 change `room-protocol` and the edit-delivery model, and a merge now would make them wait and would rewrite the model's code mappings. The question opens again when those six tasks have landed. `CatchUpEffectsPorts` (15 fields, one adapter) is outside the question: step 0b of this decision moved the catch-up interpreter out of the engine on purpose.

## Considered options

- **Effect now** (`effect@4.1.4`). The spike proved the runner, `Match.exhaustive` over effects and `TestClock`, and measured 17 KB gzip with `Data.TaggedError` or 31 KB with `Schema.TaggedError`. It is the only option that removes the promise chains and gives virtual time to the engine tests, and it costs a rewrite of 8600 lines whose only oracle is 20700 lines of room-simulation tests. A `Layer` graph over the helper port fans (22, 24, 22 and 15 callbacks) before those modules are recut would rename the fan without narrowing it. Deferred with the revisit conditions above.
- **XState v5.** A visualizer and actors, but a transition left out of a config is silent at compile time, and it is a second model of effects.
- **Continue the TASK-64 shapes.** Each module keeps its own shape and its own `never` guards. No completeness check is possible without a shared shape.

The design, the machine catalog, the type sketches, the findings folded in from the second review and the migration order live in `_bmad-output/planning-artifacts/architecture/effect-sync-core-2026-11-18/DESIGN.md`. The spike that produced the measurements is `prototypes/effect-machine-spike/`.
