# Replica machines are complete transition tables; failures are tagged results; Effect waits

At proposal time, `src/replica` holds the room's state machines in four shapes: a decision-list module (`catch-up`), injected-port modules (`generation-flow`, `room-protocol`, `roll-flow`, `room-copy`, `pending-edits`), a pure router (`command-routing`) and 1500 lines of wiring in `engine.ts`. Nothing checks that every phase answers every event: `switch` statements guarded by `never` helpers cover message kinds, not phase-event pairs, and eight pairs in `catch-up` answer with a silent empty list. Failures leave the replica through 86 `console.error` calls in seven patterns; the port failures `SendFailure` and `StorageFailure` are object literals with no exhaustive handling, and a domain verdict such as `too-large` reaches the player as "no write access". Stopping is a `stopped` flag in six modules, five epoch counters and a `stop()` of thirteen calls. The owner asked for a simpler core, typed errors, and state machines whose completeness is checked automatically.

The decision has four parts, in the order they land:

1. **Every replica state machine is a transition table.** A module exports `Phase`, `Event` and `Effect` unions and a `TransitionTable<Phase, Event, Effect>` whose type requires one cell per phase-event pair; a cell is a function or the literal `'ignore'`. A missing cell is a compile error (TS2741 in the spike). A conditional no-op inside a cell is that cell's decision and is covered by its table test, not by the shared check. A shared check walks every cell with generated data, asserts each machine's invariants and keeps a Mermaid diagram of the table in sync with the code. The modules keep running their own effects; the table replaces the `switch` and the closure variables, not the module boundary. The GM link is a second table in the catch-up module, fed by the same shell, so there is one definition of an online GM; the party-list predicate the roll flow uses is a different question and gets its own name.
2. **Lifecycle and time become ports, in plain TypeScript.** The engine owns one `AbortController` and hands its `signal` to every helper in place of `stopped: () => boolean`; one timer helper `schedule(signal, ms, fn)` replaces four timer styles and cancels itself on `abort`; subscriptions hang on `abort`; a read that returns after `stop()` is dropped by `signal.aborted`; `stop()` is one `abort()`. The five epoch counters that detect an answer superseded by a newer request stay, and are the first item of the Effect revisit. One clock port `{ now, schedule }` with an OBR and a mock adapter replaces `Date.now` and `performance.now`; moving the test rig to explicit time is a later task of its own.
3. **`better-result` replaces `src/core/result.ts` across the project.** Port failures become `TaggedError` classes in `src/platform/ports.ts` with an exhaustive `.match`. Each module decides its own policy for a failure, because only it knows whether to retry, keep the old value or wait; delivery is one sink, `report(failure: ReplicaFailure)`, whose bounded list the windows receive as a `diagnostics` notice, shown to a GM only in a collapsed settings block, and tests read instead of spying on the console. Domain verdicts keep their reason. Bugs stay thrown, which the library reports as `Panic`.
4. **Effect is deferred.** It would add a fiber runtime, `Scope`, `Queue` and `TestClock` at 17 KB gzip and a rewrite of the engine. Parts 2 and 3 take the two things it would have replaced first, so the decision is reopened on evidence: the engine tests stay racy after the clock port; places remain where one `AbortSignal` is not enough; or the `roomMessages` chain, the room-copy write mutex or the six hand-written backoffs need a second copy.

## Consequences

- `machine.ts` (the table type and `step`) and `tests/support/machine-check.ts` are plain TypeScript with `fast-check`, already a dev dependency. No runtime library enters for part 1.
- `catch-up` is the first table, because it already returns decisions as data and has 48 module tests; its eight silent pairs become declared cells. Its interpreter and timer registry then leave the engine behind an injected scheduler, about 180 lines. `room-copy`, which already names its phases, and `generation-flow` follow. `room-protocol`, `pending-edits` and `roll-flow` are judged one by one: a machine with two phases may stay a linear function.
- `better-result` is the one `Result` in the repository. Its shape differs from the current type (`status === 'ok'`, `.value`, `.error`), so the swap is one mechanical change over 48 files and 314 `.ok` checks, with no behavior change. Cost: 3.4 KB gzip, zero dependencies, TypeScript 7.0.2 compiles it. Core receives only `Result` values, plain data; the error classes live beside their ports, so ADR-0003's rule for core holds.
- Core keeps zod for the wire and the preset. UI flows keep the ADR-0002 reducer shape; a UI reducer may use the same table type when a flow has more than one phase, but nothing requires it.
- The TASK-63 and TASK-64 criterion "no shared state-machine runtime is introduced" stands: a table type, a signal and a test helper are not a runtime. What changes is the shape rule: one shape for the state of every replica machine, so one check covers them all.
- Timers remain schedulers, as CLAUDE.md requires: a timer fires an event into the table; the cell decides.
- The failure sink and the pending-edits work land after TASK-114.2, which touches the same engine lines and adds one more parse drop that should go through `report` from the start. The catch-up table does not overlap with TASK-114 and runs in parallel.
- `GLOSSARY.md` gains the two GM terms: the online GM, by messages, and the GM in the party, by the list.

## Considered options

- **Effect now** (`effect@4.1.4`). The spike proved the runner, `Match.exhaustive` over effects and `TestClock`, and measured 17 KB gzip with `Data.TaggedError` or 31 KB with `Schema.TaggedError`. It is the only option that removes the promise chains and gives virtual time to the engine tests, and it costs a rewrite of 8600 lines whose only oracle is 20700 lines of room-simulation tests. A `Layer` graph over the helper port fans (22, 24, 22 and 15 callbacks) before those modules are recut would rename the fan without narrowing it. Deferred with the revisit conditions above.
- **XState v5.** A visualizer and actors, but a transition left out of a config is silent at compile time, and it is a second model of effects.
- **Continue the TASK-64 shapes.** Each module keeps its own shape and its own `never` guards. No completeness check is possible without a shared shape.

The design, the machine catalog, the type sketches, the findings folded in from the second review and the migration order live in `_bmad-output/planning-artifacts/architecture/effect-sync-core-2026-11-18/DESIGN.md`. The spike that produced the measurements is `prototypes/effect-machine-spike/`.
