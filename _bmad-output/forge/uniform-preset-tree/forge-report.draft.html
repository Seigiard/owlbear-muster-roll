Итог

Идея закалена. Исходный вопрос «почему схема такая сложная» привёл не к реестру для билдера, а к формату v4: пять уровней с одним словарём ключей, repeat на каждом контейнере, токен как ячейка-закладка и записи значений по блоку с версией на ячейку.

Сессия началась как проверка идеи и перешла в «сделать лучше»: пять исходных предпосылок уточнились или отпали, и на их месте закреплены девять решений.

Передача в работу: forged-idea.md рядом с журналом. Он подходит на вход bmad-spec для обновления SPEC.md и формата, затем bmad-build.

Проверками, а не схемой, остаются: уникальность id в области, nameField указывает на text-поле внутри своей области, id в формулах, ширина ряда против columns. Ни одного правила «ключ зависит от другого ключа» в схеме не осталось.

Что решено

Глубина
Фиксированная: template → tab → section → row → cell. Каждый контейнер держит один вид детей. Автору, который хочет «просто список», билдер делает секцию без заголовка сам.
repeat
На шаблоне, вкладке, секции и ряду. Значит «по одному блоку на экземпляр»; вид узла решает, как блоки показаны: шаблон — листы в сайдбаре, вкладка — вкладки с «+», секция и ряд — блоки друг под другом. kind: "set" | "single" уходит: набор это шаблон с repeat. Слова «набор» и «одиночный лист» остаются подписями в билдере и глоссарии.
repeat как объект
repeat: { id, nameField } на вкладке, секции и ряду; repeat: { nameField } на шаблоне, у которого id есть и так. Три ключа, которые всегда шли вместе, стали одним объектом, и правило «только вместе» исчезло.
nameField
Имя блока принадлежит его области и заменяет правило «первое поле именует блок». Сайдбар, броски, рендер блока, «+» и подпись токена читают одно место.
Вложенные повторы
Разрешены. Адрес блока — путь пар «id области : id блока» под листом. Формула ищет id в своём блоке, потом в каждом внешнем, потом в листе. Дубликат блока копирует вложенные блоки.
Id
Только там, куда кто-то ссылается: шаблон, поле, токен-ячейка, повторяемая область. Вкладка и обычные секция и ряд без id. Смена id области стирает её блоки, как сегодня смена id шаблона стирает листы. Билдер чеканит id из заголовков, как уже делает для полей.
Токен
Ячейка { kind: "token" } и закладка: токен открывает лист, прокрученный к этой ячейке. Закладок на листе может быть несколько. Подпись — от ближайшего предка с именем: nameField блока, затем title секции, затем имя листа или title шаблона. tokens: true на шаблоне и секции уходит вместе с правилом «только с repeat».
Записи значений
Одна запись на блок, лист тоже блок: blk:<лист>[:<id области>:<id блока>]* → { order, cells }, у каждой ячейки своя тройка [значение, счётчик, автор]. Слияние по ячейке, пустая запись удаляет блок. Ключи row: и rep: уходят. Запасной вариант — запись на поле.
Видимость
На шаблоне, вкладке, секции и ряду. Узел виден, когда виден он и каждый предок. У ячейки видимости нет. Сценарий: поле заметок мастера прямо в листе персонажа.
players: "edit"
На любом шаблоне. На повторяемом значит «все игроки правят все листы набора»; доступ по игроку остаётся поверх, как сегодня.

Что отклонено

ВариантПочему нет
Только реестр для билдера поверх текущего форматаСложность идёт из нерегулярности формата, а не из отсутствия таблицы. Реестр над нерегулярным форматом особых случаев не убирает, это проверено 2026-11-12.
Свойство «из какого поля брать имя» на токен-ячейкеВторой источник имени области. Имя читают пять потребителей, токен один из них.
Токен как роль на поле (token: true)Инвентарь без поля имени не линкуется, либо tokens остаётся на шаблоне и единообразие ломается.
Id на каждом узлеId вкладки и обычной секции никто не читает. Билдер их чеканит, автор пишет, доки описывают — зря.
Запрет вложенных повторов, или одна ступеньВкладка-NPC без своих списков атак и предметов бессмысленна. Одна ступень — исключение, которое реестр должен знать.
Смешанная вложенность: ряды во вкладке, ячейки в секцииСекция без заголовка уже рисуется без него. Минус одна скобка в JSON ценой двух форм в каждом потребителе.
Запись на блок с общей версиейСамый маленький снимок, но игрок и мастер, правящие один лист в одну секунду, теряют правку.

Слабые места, которые остаются

Слияние по ячейке меняет src/core/merge.ts с «запись целиком» на «по ячейке». Это ядро синхронизации. Запасной вариант «запись на поле» существует ради этого риска.
Скрытый ряд посреди сетки columns оставит дырку или сдвинет сетку. Принято как выбор автора.
Снимок той же комнаты вырастает примерно на 60 % против сегодня: 7 436 байт против 4 644 при лимите 15 500.
Поднятый v отклоняет все текущие пресеты и снимки. Допустимо, пока живых пользователей нет.

Голоса

Один слот на область — проверка правил, не схемы. Слова «набор» и «одиночный лист» остаются подписями, меняется ключ и дискриминация типа.

Один ключ: пусть nameField живёт на каждой повторяемой области, а токен его читает. Красивая рекурсия — одна форма узла и один шаг вниз.
