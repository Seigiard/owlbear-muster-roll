- (note) Fact: SPEC.md non-goals exclude an in-extension preset editor ('presets are usually set before a game') and list 'a separate preset editor with preview' as past the POC
- (note) Fact: TASK-40 gives bun run preview: a local page that redraws a preset JSON on save; that is the owner's current editing loop
- (note) Crack (side): docs/preset-format.md:132 says upload is disabled while sheets exist; that copy is gone from src since 5.1, so the doc line is stale
- (decision) Users: everyone, owner and other GMs alike; nobody wants to write JSON
- (direction) Builder is a separate page on the deployed site (musterroll.2249364.xyz), not inside the Owlbear window: create a new preset or load a file, edit it, download the result
- (decision) v2 exchange with the room is by file: download from the extension, edit in the builder, upload to the extension. A button in the extension settings opens the builder in a new tab
- (direction) Next step after v2: the settings button passes the room's current preset to the builder in the URL, deflated (reuse encodePreset); the reverse direction stays a file
- (lock) Editing model A: a structure tree (sections, rows, cells) with a property form for the selected item, beside a live preview; a click on a cell in the preview selects it in the tree. One sheet renderer, the extension's own. Rejected: in-place editing on the sheet (second renderer), a text markup (still writing)
- (lock) Field ids: made once from the label at field creation (translit, id rules, unique), then kept when the label changes. The id shows in the field form as the name for formulas and the GM may rewrite it to short names (str, dex, wis, attr_attack). In a preset loaded from a file, a changed id warns that its stored values in the room will be erased. Formulas offer the field ids as completions
- (lock) Renaming a field id rewrites that id in every formula that can see it, by whole word (str does not touch str_tired), and says how many formulas changed. Character and NPC templates are separate scopes
- (lock) Draft and start: the builder saves one draft by itself in the page's browser storage and offers to continue it on the next visit; start from blank, from a repository example (example-preset, d20, d6-pool) or from a file; a file that fails the preset checks does not open and shows the upload's message (fixing broken JSON is not the builder's job); undo and redo for every edit
- (lock) Invalid presets while editing: intermediate invalid states are allowed; each error shows at its item in the tree and on its preview cell, with a problem counter that jumps to the first. Download is enabled only when the preset passes parsePresetFile, the upload's own check, so a downloaded file always uploads. The builder covers the whole format: both templates, section title/width/columns/repeat, every cell kind, window. Rejected: blocking edits that would make the preset invalid (forces an edit order)
- (lock) Build from parts: RAC Tree + own preset store with undo stack + hand-written forms + own preview + zod paths. Puck and other builders rejected (own data models); dummy-sheet unlicensed, ideas only
