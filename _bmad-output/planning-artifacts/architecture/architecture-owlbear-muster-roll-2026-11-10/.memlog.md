- (decision by user) Row version is a logical counter: last known plus one, ties broken by client id. A client must catch up before it edits after a freeze. Prevents clock skew deciding conflicts and keeps snapshot versions small
- (decision by user) Any GM client writes the snapshot after a pause in edits: it reads the current snapshot, merges by version, writes, then reads back to verify. Stale tabs cannot overwrite newer data. Under review: user raised using an existing CRDT library
- (decision by user) Own last-writer-wins CRDT per row, keeping one value, counter and author per row. - (decision by user) Catch-up is full state: on join or resume a client reads the snapshot and requests data; live GM clients answer with compressed full state in chunks under 16KB. Merge by version makes repeats harmless. Prevents per-row diff protocols and global counters
